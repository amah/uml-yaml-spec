# UML v0.2 classifier hierarchy — design draft

This document adds a **supplementary** classifier vocabulary to the existing v0.2 foundation. The JSON Schema fragment `schemas/v0.2/classifiers.schema.json` has now been incorporated into `schemas/v0.2/model.schema.json` under `classifierDetails`, `enumerationLiterals`, and `signalDetails`. This is still not complete UML classifier coverage.

## Target UML concepts

- `Classifier`: abstraction, generalization, specialization and redefinition.
- `Class`, `Interface`, `DataType`, `PrimitiveType`, `Enumeration`, `Signal`, `Component`.
- `Generalization`: own identity, general classifier reference, substitutability.
- `InterfaceRealization`: implementing classifier and interface contract.
- `TemplateSignature`, `TemplateParameter`, `TemplateBinding`: parameterization and substitution.

## Serialization design decisions

1. Use distinct objects for Generalization and InterfaceRealization rather than string-only lists; both are UML elements with their own properties.
2. Represent classifier flags as `flags` for now; map them individually to UML properties in the metaclass inventory.
3. Treat enumeration literals as identified elements rather than bare strings.
4. Do not conflate class inheritance with interface realization.
5. Keep owned features distinct from inherited features; inherited members are derived during semantic resolution.
6. Treat template parameterization as a first-class metamodel concern, not generic source-language type parameters.

## Outstanding before integration

- Reconcile exact UML 2.5.1 properties and inherited features against the normative XMI.
- Specify classifier-specific feature ownership, generalization-set semantics, redefinitions, substitutions and interface contracts.
- Verify integrated schema against conformance fixtures and reconcile field naming with UML 2.5.1 normative metamodel.
- Ensure existing v0.2 documents remain valid or explicitly release a breaking revision.
