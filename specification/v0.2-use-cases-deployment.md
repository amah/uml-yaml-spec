# UML v0.2 use cases and deployment — draft

This release introduces an **incomplete** vocabulary for use cases and deployment. The vocabulary is integrated into the root schema but does not yet enforce strict metaclass-specific ownership.

## Use cases

The schema recognizes `uml:Actor` and `uml:UseCase` packaged elements. A use case may declare `extensionPoints`, `subjectRefs`, and `useCaseRelationships` with `uml:Include` or `uml:Extend`. The source and target of Include and Extend have different semantics under UML 2.5.1; a semantic validator MUST enforce their type and direction. Extend relationships MUST reference extension points of the extended use case where required. Actor-to-use-case associations are represented using the general Association vocabulary, not by inventing a separate use-case link.

## Deployment

The schema recognizes `uml:Node`, `uml:Device`, `uml:ExecutionEnvironment`, `uml:Artifact`, `uml:DeploymentSpecification`, and `uml:Manifestation`. `deploymentNodes` provides a provisional nested-node representation, `communicationPaths` references connected nodes, and `deployments` reference locations and deployed artifacts.

## Limitations and conformance

- UML metaclass ownership, inherited properties, and full association-end semantics are not yet represented faithfully.
- Deployment target/deployed artifact constraints, artifact manifestations, and deployment specification semantics need further reconciliation.
- Nested nodes are provisional and not yet mapped to the complete UML composite structure.
- The schema is not equivalent to the normative OMG UML 2.5.1 XMI metamodel.
- Semantic validation MUST check reference resolution, type compatibility, duplicate IDs, and relationship constraints.
- Graphical layout and UMLDI remain separate.

Reference: https://www.omg.org/spec/UML/2.5.1
