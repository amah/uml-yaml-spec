# UML v0.2 behavior vocabulary — draft

This module introduces a limited representation of Activity and StateMachine. It is **not** full UML behavioral semantics.

## Activity

An element with `type: uml:Activity` may own `nodes` and `edges`. Every node and edge has a stable ID. Edges reference nodes by `sourceRef` and `targetRef`. Node kinds currently supported: InitialNode, ActivityFinalNode, FlowFinalNode, OpaqueAction, DecisionNode, MergeNode, ForkNode, JoinNode. Edges currently supported: ControlFlow and ObjectFlow.

Semantic validation MUST reject dangling endpoints and incompatible edge endpoints. Full token semantics, partitions, pins, structured activity nodes, exception handlers, and object-node semantics are deferred.

## State machine

An element with `type: uml:StateMachine` may own `regions`, each with `states` and `transitions`. A transition references source and target vertices by ID. A pseudostate's `kind` specifies its UML pseudostate kind.

Semantic validation MUST resolve transition endpoints within the appropriate region context and check pseudostate-specific restrictions. Nested regions, submachines, connection points, events, triggers, and executable effects remain deferred.

## Compatibility

The schema currently accepts behavior-related properties on other element kinds; this is a known limitation. Future metaclass-specific conditional constraints will restrict feature ownership.

All ID and reference rules from `v0.2-foundations.md` apply. No runtime execution semantics are specified.
