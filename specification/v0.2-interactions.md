# UML v0.2 interactions and sequence diagrams — draft

The v0.2 model schema supports `uml:Interaction` as a packaged element with owned `lifelines`, `occurrences`, `messages`, `executions`, `combinedFragments`, `interactionUses`, and `generalOrderings`.

This is a **subset** of the UML 2.5.1 Interactions package, not a complete or formally verified serialization. The representation describes sequence-diagram *semantics*, not graphical layout.

## Identity and event references

Every lifeline, occurrence, message, execution, fragment, operand, interaction use, and ordering has a stable ID. Message `sendEventRef` and `receiveEventRef` point to occurrence specifications; `coveredRef` points to a lifeline. A semantic validator MUST check references, occurrence ownership, message endpoint coverage, and ordering consistency.

## Messages

Supported message sorts: `synchCall`, `asynchCall`, `asynchSignal`, `reply`, `createMessage`, `deleteMessage`. `signatureRef` and typed `arguments` are optional. Exact UML signature and parameter matching is future work.

## Combined fragments

Supported operators: `alt`, `opt`, `loop`, `par`, `break`, `critical`, `neg`, `assert`, `strict`, `seq`, `ignore`, `consider`. Each fragment owns one or more operands, each with an optional guard and fragment references. A semantic validator MUST enforce operator-specific operand counts and consistency of covered lifelines. Nested fragment containment and full trace semantics remain future work.

## Execution specifications and interaction uses

Executions reference start and finish occurrences and a covered lifeline. Interaction uses reference a separate Interaction by `refersToRef`. A semantic validator MUST check referenced types and prevent invalid recursive expansion where applicable.

## Explicit limitations

- No visual diagram interchange or rendering coordinates.
- No complete `InteractionFragment` containment and ordering metamodel.
- No gates, continuation, state invariants, duration/time constraints, or full execution semantics.
- JSON Schema does not enforce semantic cross-reference constraints.
- This draft is not yet certified as lossless UML XMI serialization.

Authoritative UML reference: https://www.omg.org/spec/UML/2.5.1
